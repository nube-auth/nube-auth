# Custom ESLint Rules (Future Implementation)

## Rules to Prevent Internal ID Exposure

### 1. no-internal-id-in-response
Prevent exposing `.id` (internal ID) in JSON responses:

```typescript
// ❌ Fails
return c.json({ id: user.id });
return res.send({ userId: project.id });

// ✅ Passes  
return c.json({ id: user.public_id });
return res.send({ userId: project.public_id });
```

### 2. no-internal-id-in-headers
Prevent setting internal IDs in HTTP headers:

```typescript
// ❌ Fails
headers['X-User-Id'] = user.id.toString();

// ✅ Passes
headers['X-User-Id'] = user.public_id;
```

### 3. require-public-id-param
Enforce public ID naming in route parameters:

```typescript
// ❌ Fails - ambiguous naming
router.get('/:id', ...);
router.get('/users/:userId', async (c) => {
  const id = parseInt(c.req.param('userId')); // Treating as internal ID!
});

// ✅ Passes
router.get('/users/:userId', async (c) => {
  const userId = c.req.param('userId'); // Clear it's a public ID
  const user = await queries.findByPublicId(db, userId);
});
```

### 4. no-process-env-direct
Require all environment variables to go through config:

```typescript
// ❌ Fails
const key = process.env.API_KEY;

// ✅ Passes
import { env } from './config/env';
const key = env.API_KEY;
```

### 5. no-credentials-in-logs
Detect logging of potentially sensitive data:

```typescript
// ❌ Fails
log.error({ error, body: req.body }, 'Failed');
log.info({ credentials }, 'Saving');

// ✅ Passes
log.error({ userId, provider }, 'Failed');
log.info({ provider, projectId }, 'Saving');
```

## Implementation Plan

1. Create custom ESLint plugin: `@proofa/eslint-plugin`
2. Implement rules with AST parsing
3. Add to `.eslintrc.js`:
   ```js
   plugins: ['@proofa/eslint-plugin'],
   rules: {
     '@proofa/no-internal-id-in-response': 'error',
     '@proofa/no-internal-id-in-headers': 'error',
     '@proofa/require-public-id-param': 'warn',
     '@proofa/no-process-env-direct': 'error',
     '@proofa/no-credentials-in-logs': 'error',
   }
   ```
4. Run in CI/CD pipeline
5. Configure pre-commit hooks

## Testing Strategy
