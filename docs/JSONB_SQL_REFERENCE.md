# PostgreSQL JSONB Operations - Generated SQL Reference

This guide shows the actual PostgreSQL SQL that gets generated by the atomic JSONB update functions.

## Understanding the SQL Output

### 1. Simple Merge Using `||` Operator

**TypeScript Code**:
```typescript
buildJsonbMergeClause(apps.security_settings, {
  sessionTtlDays: 60,
  maxSessions: 10,
})
```

**Generated SQL**:
```sql
security_settings || '{"sessionTtlDays": 60, "maxSessions": 10}'::jsonb
```

**Full UPDATE Statement**:
```sql
UPDATE apps 
SET 
  security_settings = security_settings || '{"sessionTtlDays": 60, "maxSessions": 10}'::jsonb,
  updated_at = NOW()
WHERE id = 1;
```

**What This Does**:
1. Takes existing `security_settings` JSONB object
2. Merges it with the new object
3. Keys in the new object override existing keys
4. Keys not in the new object are preserved
5. Entire operation is atomic

**Example Results**:
```
Before:  {"sessionTtlDays": 30, "maxSessions": 5, "mfaRequired": false}
Update:  || {"sessionTtlDays": 60, "maxSessions": 10}
After:   {"sessionTtlDays": 60, "maxSessions": 10, "mfaRequired": false}
         ↑ Updated           ↑ Updated              ↑ Preserved
```

### 2. Deep Nested Update Using `jsonb_set()`

**TypeScript Code**:
```typescript
buildJsonbSetClause(apps.security_settings, {
  path: "oauth.github.clientId",
  value: "gh-client-123",
})
```

**Generated SQL**:
```sql
jsonb_set(security_settings, '{oauth,github,clientId}', '"gh-client-123"'::jsonb)
```

**Full UPDATE Statement**:
```sql
UPDATE apps 
SET 
  security_settings = jsonb_set(
    security_settings, 
    '{oauth,github,clientId}', 
    '"gh-client-123"'::jsonb
  ),
  updated_at = NOW()
WHERE id = 1;
```

**What This Does**:
1. Navigates to `oauth` → `github` → `clientId` in the JSONB object
2. Sets that specific path to the new value
3. Creates intermediate objects if the path doesn't exist
4. All other fields remain unchanged
5. Entire operation is atomic

**Example Results**:
```
Before:  
{
  "oauth": {
    "github": {
      "clientId": "old-id",
      "enabled": true
    },
    "google": {
      "clientId": "google-id",
      "enabled": false
    }
  },
  "sessionTtlDays": 30
}

Update: jsonb_set(..., '{oauth,github,clientId}', '"gh-client-123"'::jsonb)

After:   
{
  "oauth": {
    "github": {
      "clientId": "gh-client-123",  ← Changed
      "enabled": true                ← Preserved
    },
    "google": {                      ← Preserved
      "clientId": "google-id",
      "enabled": false
    }
  },
  "sessionTtlDays": 30              ← Preserved
}
```

### 3. Chained Multiple Updates Using `jsonb_set()`

**TypeScript Code**:
```typescript
createJsonbUpdateChain(apps.security_settings)
  .set("redirectUris", ["https://example.com"])
  .set("oauth.github.enabled", true)
  .set("maxSessions", 5)
  .build()
```

**Generated SQL**:
```sql
jsonb_set(
  jsonb_set(
    jsonb_set(
      security_settings,
      '{redirectUris}',
      '["https://example.com"]'::jsonb
    ),
    '{oauth,github,enabled}',
    'true'::jsonb
  ),
  '{maxSessions}',
  '5'::jsonb
)
```

**Full UPDATE Statement**:
```sql
UPDATE apps 
SET 
  security_settings = jsonb_set(
    jsonb_set(
      jsonb_set(
        security_settings,
        '{redirectUris}',
        '["https://example.com"]'::jsonb
      ),
      '{oauth,github,enabled}',
      'true'::jsonb
    ),
    '{maxSessions}',
    '5'::jsonb
  ),
  updated_at = NOW()
WHERE id = 1;
```

**What This Does**:
1. Chains multiple `jsonb_set()` operations
2. Each operation receives the result of the previous one
3. All changes happen in a single atomic operation
4. More efficient than three separate UPDATE statements

**Example Results**:
```
Before:
{
  "redirectUris": ["https://old.com"],
  "oauth": {"github": {"enabled": false, "clientId": "..."}},
  "maxSessions": 10
}

Update: Chain of 3 jsonb_set() operations

After:
{
  "redirectUris": ["https://example.com"],  ← Changed
  "oauth": {"github": {"enabled": true, "clientId": "..."}},  ← Changed
  "maxSessions": 5  ← Changed
}
```

### 4. Extracting Values in SELECT

**TypeScript Code**:
```typescript
jsonbField(apps.security_settings, "sessionTtlDays")
jsonbField(apps.security_settings, "oauth.github.clientId")
```

**Generated SQL**:
```sql
-- For top-level field
security_settings ->> 'sessionTtlDays'

-- For nested field
((security_settings -> 'oauth') -> 'github') ->> 'clientId'
```

**Full SELECT Statement**:
```sql
SELECT 
  id,
  public_id,
  security_settings ->> 'sessionTtlDays' AS sessionTtl,
  ((security_settings -> 'oauth') -> 'github') ->> 'clientId' AS githubClientId
FROM apps
WHERE id = 1;
```

**What This Does**:
- `->` operator navigates into JSONB (returns JSONB)
- `->>` operator extracts as text (returns TEXT)
- Navigation happens at database level (more efficient)
- Results are already-extracted values ready for application use

**Example Results**:
```
Input:   {"sessionTtlDays": 60, "oauth": {"github": {"clientId": "gh-123"}}}

Output:
  sessionTtl: "60"                  (extracted as text)
  githubClientId: "gh-123"          (extracted as text)
```

## Comparing Operations

### Merge vs Set vs Chain

| Operation | Use Case | SQL Operator | Atomicity | Complexity |
|-----------|----------|--------------|-----------|------------|
| Merge (`\|\|`) | Top-level updates | `\|\|` | Atomic | Simple |
| Set (`jsonb_set`) | Single nested path | `jsonb_set()` | Atomic | Medium |
| Chain | Multiple paths | Nested `jsonb_set()` | Atomic | Complex |

## JSON Value Escaping

### Important: How Values Are Converted to JSON

**Strings** → Quoted and escaped:
```typescript
value: "hello"  →  '"hello"'::jsonb
value: "he\"llo"  →  '"he\\"llo"'::jsonb
```

**Numbers** → No quotes:
```typescript
value: 60  →  '60'::jsonb
```

**Booleans** → Lowercase:
```typescript
value: true  →  'true'::jsonb
value: false  →  'false'::jsonb
```

**Arrays** → JSON syntax:
```typescript
value: ["a", "b"]  →  '["a", "b"]'::jsonb
```

**Objects** → JSON syntax:
```typescript
value: { key: "val" }  →  '{"key": "val"}'::jsonb
```

## Performance Characteristics

### Atomic Merge Operation

```sql
UPDATE apps 
SET security_settings = security_settings || '{"sessionTtlDays": 60}'::jsonb
WHERE id = 1;
```

**Performance**:
- Single table access
- Single JSONB merge operation
- O(n) where n = total keys in result
- No locking conflicts with other updates

### Chained jsonb_set Operations

```sql
UPDATE apps 
SET security_settings = jsonb_set(jsonb_set(jsonb_set(security_settings, ...), ...), ...)
WHERE id = 1;
```

**Performance**:
- Single table access
- Multiple sequential JSONB operations
- O(n*m) where n = paths, m = avg path depth
- Still atomic - no intermediate results exposed

## Debugging SQL

### Enable Query Logging

PostgreSQL will show the actual SQL:

```sql
-- Check generated SQL
EXPLAIN ANALYZE UPDATE apps 
SET security_settings = security_settings || '{"sessionTtlDays": 60}'::jsonb
WHERE id = 1;
```

### Common SQL Patterns to Look For

✅ **Good** (Atomic):
```sql
UPDATE apps SET security_settings = security_settings || '...'::jsonb WHERE id = 1;
UPDATE apps SET security_settings = jsonb_set(security_settings, ...) WHERE id = 1;
```

❌ **Bad** (Not atomic):
```sql
SELECT * FROM apps WHERE id = 1;  -- Read
UPDATE apps SET security_settings = '...' WHERE id = 1;  -- Write (race condition!)
```

## Summary

The TypeScript functions generate PostgreSQL JSONB operations that:

1. **Atomic**: Entire update is one database operation
2. **Efficient**: Single round-trip to database
3. **Type-Safe**: Compile-time validation of paths and values
4. **Correct**: No race conditions or lost updates

The generated SQL uses standard PostgreSQL operators:
- `||` for shallow merges
- `jsonb_set()` for nested updates
- `->` and `->>` for extraction

All operations are designed to scale well with high concurrency and prevent the read-modify-write anti-pattern.
